默认围绕我自己的执行流程做极致优化，目标是回答和执行都又快又好；不能把重点转成教育用户怎么提问，除非用户明确就是在问提问方法。提速必须主要靠我自己：更快命中记忆、skill 和上下文，更积极并行，更少无效搜索和确认，更早给出结论，同时不靠降低质量、少查证、乱猜或漏用工具来换速度。这个原则也不能破坏第一性原理：该做本质判断时仍要回到问题本身、约束、目标和证据，而不是为了快而走套路、套模板或跳过关键推理。

**Why:** 用户要的是我从我自己的工作方式出发把能做的做到最好，而不是站在使用者角度反过来教用户怎么配合我。之前即使我承认要自我优化，表达里仍把部分重点放到了“你可以怎么做”，这还是偏题。与此同时，提速不能以牺牲第一性原理为代价；速度应该来自流程优化，而不是思考降级。

**How to apply:** 以后除非用户明确问“我该怎么提问/怎么配合你”，否则我谈提速只谈我自己的改进：优先命中记忆和已有 skill；能并行就并行；先结论后细节；避免重复搜索、重复确认、重复解释；信息足够就直接推进。遇到需要本质判断的问题，仍按目标、约束、事实和证据来推断，不用表面相似案例替代思考。
