# 三、直接给你可执行的重构方案（重点）

## ✅ 第一刀：砍掉 `Action → Gateway`

### 你现在：

```ts
ActionModule imports: GatewayModule ❌
```

### 为什么错？

* Action 是“业务动作层”
* Gateway 是“设备/通信层”

👉 **Action 不应该感知 Gateway**

---

### ✅ 正确做法

把 Gateway 的能力抽出来：

## 👉 新建一个模块：`DeviceModule`（核心）

```ts
@Module({
  providers: [
    DeviceCommandService,
    DeviceRegistryService,
    DeviceAllocatorService,
  ],
  exports: [
    DeviceCommandService,
    DeviceRegistryService,
    DeviceAllocatorService,
  ],
})
export class DeviceModule {}
```

---

### 然后改：

#### ❌ ActionModule

```ts
imports: [GatewayModule]
```

#### ✅ 改成

```ts
imports: [DeviceModule]
```

---

### 👉 GatewayModule 也改：

```ts
imports: [DeviceModule]
```

---

### 🔥 结果

```
Action → Device
Gateway → Device
```

👉 **完全解耦（关键一步）**

---

## ✅ 第二刀：砍掉 `Execution ↔ Action`

你现在：

```ts
Execution imports Action ❌
Action imports Strategy → Gateway → Execution ❌
```

---

### 👉 正确结构

```
Action → Execution ❌（不要）
Execution → Action ❌（也不要）
```

---

### ✅ 解决方案：用“接口 + 事件”

#### 方式 1（推荐）：事件驱动

```ts
// execution.service.ts
this.eventBus.emit('action.execute', payload);
```

```ts
// action.listener.ts
@OnEvent('action.execute')
handle(payload) {}
```

👉 Execution 不再 import Action

---

#### 方式 2：抽接口（更工程化）

```ts
export interface ActionExecutor {
  execute(...)
}
```

Execution 只依赖接口，不依赖模块

---

## ✅ 第三刀：砍掉 Kafka ↔ Scheduler（这个最容易）

```ts
KafkaModule imports Scheduler ❌
SchedulerModule imports Kafka ❌
```

---

### ✅ 正确结构

```

Kafka ❌ 不依赖 Scheduler
```

---

### 👉 修改：

#### ❌ KafkaModule

```ts

```

### 👉 KafkaConsumer 不要直接调 Scheduler

改成：


### Scheduler：


---

### 🔥 结果

```
Kafka → EventBus → Scheduler
```

👉 解耦完成

# 四、最终正确架构（给你一个目标状态）

```
                ┌────────────┐
                │  Gateway   │
                └─────┬──────┘
                      ↓
                ┌────────────┐
                │  Device    │
                └─────┬──────┘
                      ↓
Action ─────────→ Execution ─────────→ Strategy
                      ↓
                ┌────────────┐
                │ Scheduler  │
```

### 关键规则：

* ❌ 不允许回头依赖
* ❌ 不允许横向互调
* ✅ 统一通过：

  * Device（基础能力）
  * EventBus（解耦）
